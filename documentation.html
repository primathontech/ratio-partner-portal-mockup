Getting started

Every app on Ratio starts the same way: create an organisation, create an app, and test it against your own dev store before you ever touch a merchant's data.

1. Create your organisation — this is the workspace your apps, stores and team live in.
2. From Apps, click Create app and choose the scopes it needs.
3. Every organisation gets one dev store under Stores → Dev to build against.
4. When you're ready, submit for review from the app's Overview tab.

Authentication

Ratio apps use standard OAuth 2.0. Your app redirects the merchant to Ratio, the merchant approves the scopes you requested on the install consent screen, and Ratio redirects back with an authorization code.

POST https://{store}.ratio.win/oauth/token Content-Type: application/json { "client_id": "88ec0cdbfdf25eea1dcd339433b662", "client_secret": "{your_client_secret}", "code": "{authorization_code}", "grant_type": "authorization_code" }

The response carries an access token scoped exactly to what the merchant approved — never more. Tokens are refreshed the same way as Shopify's: there is no silent re-authorization.

Find your Client ID and Client secret, and regenerate them if compromised, from any app's API keys tab.

Webhooks

Subscribe to platform events — orders/create, app/uninstalled, customers/data_request and others — and Ratio POSTs a signed JSON payload to your endpoint as they happen. There's no dashboard "save a webhook" step: you declare subscriptions one of two ways, and an app's Webhooks tab only shows what's currently active, read-only.

Declarative — topics and delivery URLs declared in your app's manifest. They take effect when that version is published, or when a merchant installs it — never silently.
Programmatic — call the Webhooks API at runtime to register or unregister a subscription. Takes effect immediately, and can vary per merchant.

You can subscribe to the same topic more than once — up to 16 independent subscriptions per (app, topic, merchant) — so your core logic and an internal analytics forwarder can both listen to orders/create without you building your own fan-out. Each subscription gets its own signing secret and its own delivery/retry log.

{ "topic": "orders/create", "shop_domain": "wellversed.ratio.win", "payload": { "id": "ord_8f21ac", "total": "2499.00", "currency": "INR" } }

Extensions

Extensions are how an app shows up somewhere other than its own page — on a storefront or inline in Ratio admin. There are three types today; configure them from an app's Extensions tab.

  • Theme app block — UI the merchant drags into a specific spot on a storefront page in the theme editor.
  • Theme app embed — UI or script that runs globally, once the merchant flips an on/off switch in Theme settings.
  • Admin UI extension — an action, an inline card, or a print view rendered natively inside Ratio's merchant admin.
